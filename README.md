# کویرتایر — افزونه‌ی خرید سریع (Chrome Extension)

افزونه‌ی کروم برای **پایش سبک موجودی** و **خرید سریع** از `kavirtire.ir` بدون رفرش مکرر صفحه.
جایگزین بازنویسی‌شده و سخت‌شده‌ی اسکریپت Tampermonkey «KavirTire V4» است.

## فایل نصب

| فایل | توضیح |
|---|---|
| **`dist/kavirtire-fastbuy-v1.0.0.zip`** | بسته‌ی آماده‌ی نصب (Load unpacked → انتخاب پوشه) |
| `extension/` | سورس افزونه (همین را هم می‌توانید مستقیم بارگذاری کنید) |
| `tools/preview-panel.html` | پیش‌نمایش ظاهر پنل در مرورگر |
| `tools/preview-trace.html` | پیش‌نمایش تب «لاگ حرفه‌ای» |
| `tools/preview-qty.html` | پیش‌نمایش تب پرداخت + جعبه‌ی تعداد |
| `tools/mock-site/` | سایت شبیه‌سازی‌شده برای تست بدون کویرتایر |
| `tools/test/harness.js` | تست خودکار منطق افزونه |

---

## نصب

۱. فایل `dist/kavirtire-fastbuy-latest.zip` را از ریپازیتوری دانلود و **استخراج** کنید.
۲. در کروم به `chrome://extensions` بروید.
۳. **حالت Developer mode** را روشن کنید (بالا سمت راست).
۴. روی **Load unpacked** بزنید و **پوشه‌ی استخراج‌شده** (که `manifest.json` دارد) را انتخاب کنید.
۵. `https://kavirtire.ir/esale/products` را باز کنید — پنل «خرید سریع» بالا-چپ ظاهر می‌شود.

> نکته: به‌جای ZIP می‌توانید در همان صفحه **Load unpacked** پوشه‌ی `extension/` را مستقیماً انتخاب کنید.

**میان‌برها:** `Alt+Shift+K` شروع/توقف پایش · `Alt+Shift+P` نمایش/پنهان‌کردن پنل
(هر دو در `chrome://extensions/shortcuts` قابل تغییرند.)

## چطور کار می‌کند؟

### ۱) بدون رفرش مکرر — API سبک به‌جای نوکردن صفحه
اسکریپت قبلی صفحه را چند بار در دقیقه نو می‌کرد (گران، پرریسک برای بن). این افزونه فقط
`GET /esale/products/availability` را می‌گیرد (پاسخ چند کیلوبایتی JSON) و پایش در اسکریپت
سایت انجام می‌شود؛ صفحه هیچ‌گاه رفرش نمی‌شود.

### ۲) ضدبن — چهار لایه‌ی محافظت
| لایه | کار |
|---|---|
| **بودجه‌ی نرخ سراسری** | در همه‌ی تب‌ها یک پنجره‌ی مشترک: سقف درخواست در دقیقه + حداقل فاصله + jitter |
| **احترام به 429/403/503** | خواندن `Retry-After`، Backoff نمایی، توقف کامل تا پایان مهلت |
| **Circuit breaker** | چند خطای پشت‌سرهم → استراحت طولانی خودکار (پیش‌فرض ۱۰ دقیقه) |
| **مالکیت تک‌تبی** | اگر تب دیگری پایش می‌کند، تب دوم شروع نمی‌کند تا درخواست‌ها دوبل نشوند |

علاوه بر این، هر پاسخ `419` (نشست منقضی) پایش را فوراً متوقف می‌کند تا درخواست‌های بیهوده نرود.
پیش‌تنظیم پیشنهادی: **متعادل** (~۵۰ درخواست در دقیقه سقف سخت؛ در عمل با فاصله‌ی ۱٫۲ ثانیه).

### ۳) انتخاب سریع محصول
- انتخاب چندگانه با **جست‌وجو** و **اولویت** (▲▼) — اولویت‌دارها زودتر بررسی می‌شوند
- دکمه‌ی **⚡ خرید فوری** روی هر کارت محصول و در پنل (بدون منتظر ماندن)
- **خط مبنا**: محصولی که از قبل موجود است به‌اشتباه خریداری نمی‌شود؛ فقط لحظه‌ی
  «ناموجود → موجود» خرید محسوب می‌شود (قابل تغییر با «خرید محصول از قبل موجود»)

### ۴) رفتن سریع تا درگاه — هدف: **زیر ۲ ثانیه**
| مرحله | روش سریع |
|---|---|
| افزودن به سبد | `$call('add')` روی Livewire + تشخیص موفقیت از **پاسخ شبکه** (نه انتظار DOM) |
| ناوبری | ریدایرکت خودکار Livewire از `effects.redirect` خوانده می‌شود؛ فالبک فقط اگر نبود |
| انتخاب درگاه | درگاه‌ها **داینامیک** کشف می‌شوند (`wire:click*="setGateway("`) — کلید ثابت فرض نمی‌شود |
| کلیک پرداخت | اولین دکمه‌ی فعال، بدون انتظار ۱۲ ثانیه‌ای |
| تشخیص انتقال | از پاسخ شبکه، نه تغییر DOM |

اگر درگاه تنظیم‌شده در صفحه نبود، بسته به `gatewayStrategy` یا **اولین** درگاه یا **تصادفی** انتخاب می‌شود.

> اگر سبد شامل آیتم دیگری هم باشد، افزونه برای جلوگیری از پرداخت اشتباه، به حالت **دستی** برمی‌گردد.

### ۵) تعداد حلقه — پیش‌فرض ۲
در صفحه‌ی پیش از درگاه، افزونه تعداد را **خودکار روی ۲** تنظیم می‌کند (حداکثر ۲).

تنظیم تعداد کاملاً **داینامیک** است و همه‌ی پیاده‌سازی‌های ممکن را امتحان می‌کند:

| روش | تشخیص |
|---|---|
| `input[type=number]` | مقداردهی با رویدادهای `input`/`change`/`blur` (نیاز Livewire) |
| `select` | انتخاب گزینه‌ی ۲ |
| دکمه‌ی `+` | کلیک تکراری تا رسیدن به ۲ (با بازخوانی مقدار) |
| دکمه‌ی عددی «۲» | کلیک مستقیم |
| متد Livewire | `setQty` / `setQuantity` / `setCount` / … |

هر روش با **خواندن مقدار واقعی** تأیید می‌شود؛ اگر مؤثر نبود، روش بعدی امتحان می‌شود.
در پنل (تب پرداخت) با `−`/`+` قابل تغییر است: **۱ تا ۱۰**.
گزینه‌ی «اگر تعداد ست نشد، پرداخت نکن» برای ایمنی بیشتر.

### ۶) سرعت: کل مسیر زیر ۲ ثانیه
چهار تغییر ساختاری:

| مشکل | راه‌حل |
|---|---|
| `run_at: document_idle` — افزونه تا لود کامل صبر می‌کرد | `document_end` + شروع بدون انتظار |
| `K.ready` بلاک بود؛ ۲ ثانیه تأخیر در بدترین حالت | Snapshot همگام `localStorage` + hot-apply تنظیمات |
| مراحل پرداخت **سری** بودند (سبد → تعداد → درگاه → پرداخت) | `Promise.all`: سبد + تعداد + درگاه **هم‌زمان** |
| انتظارهای ثابت ۱.۲s / ۲.۵s / ۳s | ۴۰۰ms درگاه · ۱.۴s دکمه · ۱.۸s ریدایرکت |

زمان‌سنج واقعی «موجود شد → درگاه باز شد» در پنل و Trace ثبت می‌شود:
`⏱ موجود شدن → درگاه: 1,487ms ⚡`

> بر روی شبکه‌ی کند یا سرور شلوغ، این عدد بیشتر می‌شود؛ در تب «لاگ حرفه‌ای»
> می‌بینید کدام مرحله زمان برده و می‌توانید در «سرعت خرید» تنظیم کنید.

### ۷) لاگ حرفه‌ای — تب چهارم پنل
کاملاً جدا از لاگ کاربر عادی. هر اقدام ربات با **مرحله، مدت‌زمان و کد خطا** ثبت می‌شود:

```
PAY   | کلیک درگاه        | 142ms | gwAfter=refahk
ADD   | درج در سبد موفق    | 421ms | how=livewire-redirect
ADD   | شکست افزودن        | 4820ms | ADD_NOT_SELECTED  ← کلیک برای دیدن دیف
```

- **دلایل شکست** به‌صورت چیپ گروه‌بندی می‌شود (`ADD_NOT_SELECTED ×3`) — با کلیک، فقط همان رکوردها
- روی هر ردیف کلیک کنید: **داده‌ی تشخیصی** (وضعیت کارت، پاسخ شبکه، مراحل) باز می‌شود
- **JSON** برای تحلیل/download · **کپی** متن خوانا · **پاک**
- لاگ در `chrome.storage` هم ذخیره می‌شود (پس از بستن تب قابل بازیابی)

**کدهای خطا:** `ADD_NO_ELEMENT` · `ADD_NO_METHOD` · `ADD_UNAVAILABLE` · `ADD_NOT_SELECTED` ·
`ADD_SERVER_419` · `ADD_SERVER_429` · `ADD_TIMEOUT` · `NAV_FAILED` · `PAY_NO_CART` · `PAY_NO_GWBTN` ·
`PAY_NO_PAYBTN` · `PAY_NO_NAV` · `WATCH_429` · `WATCH_419`

### ۸) باگ‌های کشف‌شده از لاگ واقعی
| باگ | علت | رفع |
|---|---|---|
| هر تلاش افزودن ۴ ثانیه | انتظار `product-selected` که هرگز نمی‌آمد | تشخیص از پاسخ Livewire؛ بازرسی هر ۲۵ms |
| «⏹ خرید موفق» دروغین | توقف قبل از موفقیت واقعی لاگ می‌شد | پیام فقط بعد از درج قطعی در سبد |
| خرید دوباره ممکن نبود | خط مبنا بعد از شکست ریست می‌شد | خط مبنا حفظ + محصول ناموفق دوباره کاندید می‌شود |
| `ADD_UNAVAILABLE` کاذب | `wire:snapshot` صفحه کهنه است | snapshot دیگر مانع افزودن نیست؛ پاسخ سرور ملاک است |
| تعداد ۲ حلقه کار نمی‌کرد | `K.site.click(plus)` شئ پاس می‌داد نه المان | `plus.el` + کلیک مقاوم به نبود `PointerEvent` |

## ساختار پروژه

```
extension/
├── manifest.json              MV3 — بدون نیاز به build
├── icons/                     ۱۶ تا ۱۲۸ پیکسل
└── src/
    ├── shared/defaults.js     تنظیمات، پیش‌تنظیم‌ها، ادغام امن
    ├── bridge.js              پل ISOLATED ↔ MAIN (postMessage + Port)
    ├── background.js          سرویس‌ورکر: ذخیره‌سازی، اعلان، تب، badge
    ├── options.html/css/js    صفحه‌ی تنظیمات کامل
    └── content/               (دنیای MAIN، دسترسی کامل به Livewire)
        ├── core.js            باس رویداد، تنظیمات، صدا/اعلان/فوکوس تب
        ├── trace.js           موتور لاگ حرفه‌ای (span/step/diag/کد خطا)
        ├── qty.js             تعیین تعداد حلقه (input/+/select/API)
        ├── trace-viewer.js    تب «لاگ حرفه‌ای» در پنل
        ├── net.js             مشاهده‌ی fetch/XHR (۱ قبل از Livewire)
        ├── guard.js           بودجه‌ی نرخ، Backoff، 429، breaker
        ├── site.js            آداپتر DOM/API کویرتایر (تنها نقطه‌ی وابسته به سایت)
        ├── engine.js          موتور پایش، خط مبنا، افزودن به سبد
        ├── payment.js         انتخاب درگاه و پرداخت خودکار
        ├── panel.js           پنل شناور (Shadow DOM) + تب‌ها
        └── main.js            مسیریابی، SPA، میان‌بر، overlay، keep-awake
tools/
├── make_icons.py             ساخت آیکون‌ها (بدون وابستگی)
├── build.sh                  ساخت ZIP
├── preview-panel.html        پیش‌نمایش پنل
├── mock-site/server.js       سایت شبیه‌سازی‌شده برای تست
└── test/harness.js           ۲۴ تست خودکار (jsdom)
```

**نکته‌ی طراحی:** همه‌ی چیزهایی که به سایت بستگی دارد (انتخابگرها، آدرس API، دکمه‌ها)
تنها در `site.js` و تنظیمات «پیشرفته» هستند. اگر کویرتایر DOM را عوض کند، فقط یک فایل لازم است.

## اجرای تست‌ها

```bash
# تست منطق افزونه در محیط شبیه‌سازی‌شده
npm i --no-save jsdom@24
JSDOM_PATH=$(pwd)/node_modules/jsdom node tools/test/harness.js

# سایت شبیه‌سازی‌شده (پنل تست گوشه‌ی صفحه: + و − موجودی، ۴۲۹ دستی)
node tools/mock-site/server.js   # http://localhost:8123/esale/products
```

## تست یکپارچه (۴۸ تست)

```bash
npm i --no-save jsdom@24
JSDOM_PATH=jsdom node tools/test/harness.js
```

پوشش: تشخیص موجودی، خط مبنا، سرعت افزودن، snapshot کهنه، ۴۲۹/backoff،
بودجه‌ی نرخ، پرداخت خودکار، **تعداد حلقه (input/+/متن)**، **زیر ۲ ثانیه**، و ساختار لاگ حرفه‌ای.

```bash
bash tools/build.sh
```

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| پنل نمایش داده نمی‌شود | صفحه‌ی `/esale/products` را نوسازی کنید؛ افزونه فقط در `/esale/*` فعال است |
| «دکمه‌ی درگاه پیدا نشد» | در پنل → تب **پیشرفته** → `cardSelector`/درگاه‌ها را تنظیم کنید یا درگاه را دستی انتخاب کنید |
| «نشست منقضی شده» | یک‌بار از حساب خارج و وارد شوید، سپس پایش را دوباره شروع کنید |
| محصول موجود است ولی خرید نمی‌شود | گزینه‌ی «خرید محصولی که از قبل موجود است» را روشن کنید یا ⚡ خرید فوری را بزنید |
| کندی عمدی بعد از ۴۲۹ | رفتار درست است؛ افزونه برای بن نشدن عقب می‌کشد |
| خرید کند است (>۲s) | تب **لاگ حرفه‌ای** → ببینید کدام مرحله `ms` بالا دارد؛ سپس `addTimeout`/`payBtnWait` را تنظیم کنید |
| «سرور محصول را انتخاب نکرد» | `ADD_NOT_SELECTED`: سرور add را نپذیرفت؛ پاسخ شبکه در دیف همان رکورد است |
| دکمه‌ی درگاه پیدا نشد | `PAY_NO_GWBTN`: انتخابگر درگاه تغییر کرده — کلیدها در تنظیمات «لیست درگاه‌ها» قابل بازنویسی است |
| تعداد ۲ نشد | `PAY_QTY_FAILED` در لاگ حرفه‌ای: `tried` نشان می‌دهد چه روش‌هایی امتحان شد؛ اگر هیچ‌کدام نبود، کنترل تعداد با روش جدید اضافه می‌شود |
| از ۲ ثانیه بیشتر شد | مرحله‌ی کند را در لاگ ببینید (`ms` هر گام) و `addTimeout`/`payBtnWait`/`navWait` را تنظیم کنید |

## حریم خصوصی و مسئولیت

- هیچ داده‌ای به بیرون فرستاده نمی‌شود؛ همه‌چیز محلی و روی `kavirtire.ir` است.
- افزونه «رفرش مکرر» را حذف می‌کند، اما هیچ روشی نمی‌تواند صددرصد تضمین کند سرور
  درخواست‌ها را محدود نکند. با سرعت محافظه‌کارانه استفاده کنید.
- استفاده از افزونه و رعایت قوانین سایت بر عهده‌ی کاربر است.
